## Short Polling
When people say just "polling", they are usually referring to Short Polling.

This is a very common pattern where a request naturally takes a long time to process. The processing can happen asynchronously on the backend, and the client can "poll" the status of that job, using some kind of handle which maps to the job processing on the backend.

Polling is often used to address scenarios for which request/response is not a good fit.

Process of short polling:
1. Client sends a request
2. Server immediately responds with a handle/identifier
3. The server continues to process the request
4. The client uses the handle it was given to check for the status

This approach also allows the client to disconnect whilst the request is still processing.

There are cons for this approach however:
* It is very "chatty" and relatively wasteful of backend resources, as each poll request is not doing any meaningful work.
* This can be particularly bad for highly used apps that are hosted on cloud services that bill per-request.

## Long Polling
Long Polling is the same as the above approach, however, when the client sends a poll request, the server does not respond until the job has completed.

Process of long polling:
1. Client sends a request
2. Server immediately responds with a handle/identifier
3. Server continues to process the request
4. Client uses that handle to check for status

Long polling is the approach used by Apache Kafka - a popular open source messaging system. When subscribers are connected to a topic, a long poll request is held open, and Kafka will only reply when a message has come through for the subscriber.
